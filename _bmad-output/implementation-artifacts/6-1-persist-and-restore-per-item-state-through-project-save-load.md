# Story 6.1: Persist and restore per-item state through project save/load

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a sound designer,
I want my animation bindings and per-item settings to survive saving and reopening a project,
so that I don't reconfigure anything when I come back to a session.

## Acceptance Criteria

From [epics.md Story 6.1](../planning-artifacts/epics.md) (FR31, FR33, D9; NFR-R2). This is the **first Epic 6 story** and the first that turns `SaveState`/`LoadState` from empty stubs ([pcm_source_anim.cpp:84-85](../../src/pcm_source_anim.cpp#L84-L85)) into a real round-trip.

1. **AC1 — Per-item binding round-trips via `SaveState`/`LoadState` (FR31, FR33, D9).** Given a project with several animation items and (optionally) adjusted per-item settings, when the project is saved and reopened **on the same machine**, each item's **animation file path** round-trips so the item is restored. The path is carried as line-based `key=value` text in our PCM_source's project sub-chunk (D9, [architecture.md:580-596](../planning-artifacts/architecture.md#L580)). **The mechanism is verify-first:** Reaper natively writes a `FILE "…"` line for any source whose `GetFileName()` is non-empty (ours is — [pcm_source_anim.cpp:68](../../src/pcm_source_anim.cpp#L68)) and on load recreates the source via the registered `CreateFromType("RAV_ANIM")` factory then calls `SetFileName()` with the (relinked) path. So the path **may already** ride natively; this story (a) **confirms** that in-Reaper and (b) implements `SaveState`/`LoadState` as a real, forward-compatible framework that **defensively** persists `file=` as well, applied on load **only if the native path is still empty** (so the native/relinked path always wins — keeps Story 6.3 native, see AC4).
2. **AC2 — Every reopened item rebinds and plays with no manual action.** After reopen, each animation item **rebinds to its file** and plays under the playhead exactly as in Stories 4.3–4.5 — **no empty item, no broken item, no "offline media", no manual re-drop**. This is **end-to-end**: restoration must leave the existing transport→display pipeline working (the viewer's `GetCurrentAnimItem` poll finds the rebound item, lazily loads its asset on path-change, and the playhead drives the frame — all **unchanged** from Epic 4; 6.1 only has to make the source come back **with its path**, the rest is already wired).
3. **AC3 — Forward-compat: `LoadState` ignores unknown keys; never hard-fails.** `LoadState` parses `key=value` lines, **silently ignores any key it doesn't recognize** (a newer project opened by an older extension, or Reaper's own native lines such as the uppercase `FILE` line / nested `<…>` blocks), and **returns success (`0`), never `-1`, on a merely-unknown or malformed line** — a single bad line must not abort the load or drop the item (PRD "older extension reading newer project: opportunistic"; [architecture.md:329](../planning-artifacts/architecture.md#L329)). Only a genuinely unrecoverable context error returns `-1`.
4. **AC4 — `SaveState` is data-loss-safe and 6.3-compatible (NFR-R2).** `SaveState` writes **only our own `key=value` lines into our own source sub-chunk** via `ProjectStateContext::AddLine` — it **must not** corrupt the project file, drop tracks, touch any other Reaper state, or call any Reaper **mutation** API ([NFR-R2](../planning-artifacts/prd.md#L447); [architecture.md:1020](../planning-artifacts/architecture.md#L1020)). The defensive `file=` we write must **never override** a path Reaper has natively relinked: `LoadState` applies `file=` to `SetFileName` **only when the current path is empty**, so on a moved/relinked project (Story 6.3) the native path always wins — the persisted `file=` is a fallback, never an authority. No-throw, main-thread-only (D5/AR18): both methods run on the thread Reaper drives save/load on; guard every pointer (`ctx`, `firstline`, every parsed buffer).
5. **AC5 — No regression, scope-tight, deferrals documented.** Every Epic 1–4 behavior is unchanged: drop→sized-named item (4.2), playhead→frame (4.3), native move/resize/left-trim/color/rename + coexistence (4.4), overlap→topmost-track selection (4.5); the `pcmsrc` factory still registers/deregisters **symmetrically with the same pointer** (`plugin_main.cpp` **untouched** — `SaveState`/`LoadState` are PCM_source **virtuals Reaper calls**, **not** a new `rec->Register`, so the boundary rule is preserved with **no** registration added); static meshes still render; foreign files are not hijacked; unload/quit does not crash. The **only** production code is in `src/pcm_source_anim.cpp` (the two method bodies + a small `key=value` (de)serialize helper). **No new Reaper symbol** (`ProjectStateContext`/`PCM_source` are SDK types already included via [reaper_api.h](../../src/reaper_api.h); `AddLine`/`GetLine` are virtuals on the handed-in objects — **`reaper_api.h` is NOT touched**), **no `CMakeLists.txt` change** (`pcm_source_anim.cpp` is already in `SOURCES`), **no new dependency**. **Out of scope, deferred (Task 5):** per-item **camera framing** persistence (the camera is **global** today — renderer-owned `OrbitCamera`, reset on `SetAsset`; there is **no per-item camera state to persist yet**); **`time_offset`** (= take `D_STARTOFFS`, **already native** take state Reaper persists — not ours to write); **`time_scale`** (= take `D_PLAYRATE`, **native + already deferred** from 4.4); **panel/viewport dock state** (= **Story 6.2**); **cross-machine relink verification** (= **Story 6.3**). Build stays `/W3 /permissive-` warning-free (NFR-R5).

> **Scope boundary (read before coding):** This story makes per-item state **survive save/reopen** by implementing `AnimSource::SaveState`/`LoadState` (D9). The **only production code** is in `src/pcm_source_anim.cpp`: (a) a tiny `key=value` writer + line parser, (b) `SaveState` emitting our known keys via `ctx->AddLine`, (c) `LoadState` looping `ctx->GetLine`, parsing each line, ignoring unknowns, and applying `file=` **only if the path is empty**. It does **NOT**: write the file path in a way that can override Reaper's native relink (the `file=` we write is a load-time fallback only — Story 6.3 stays native); persist **per-item camera** (camera is global today — deferred); persist **`time_offset`/`time_scale`** (native take `D_STARTOFFS`/`D_PLAYRATE` — not ours); persist **panel/dock** state (Story 6.2); add any `rec->Register`, `WANT_` symbol, dependency, or `CMakeLists`/`plugin_main`/`renderer`/`viewer_window`/`asset_loader` edit; or change the transport→display pipeline (restoration rides the **existing** 4.3–4.5 poll/load path unchanged). **The proof 6.1 works:** drop 2–3 animation items (different files / positions / tracks) → **Save** → close → **reopen** the project → every item is back, bound to its file, and **plays under the playhead with no manual action**; no empty/broken/offline item; saving never corrupts the `.rpp` or touches other tracks.

## Dev Notes

### What this story is — turn the persistence stubs real, verify-first (AC1, AC2)

Epic 6's premise is "today nothing is persisted — `SaveState`/`LoadState` are empty stubs" ([sprint-change-proposal-2026-06-27.md §1](../planning-artifacts/sprint-change-proposal-2026-06-27.md); [pcm_source_anim.cpp:84-85](../../src/pcm_source_anim.cpp#L84)). 6.1 closes exactly that hole **for per-item state**. The subtlety to internalize **before coding** (Task 0): the **file path may already round-trip natively**. Reaper writes a `FILE "…"` line for any source whose `GetFileName()` is non-empty (ours is — [pcm_source_anim.cpp:68](../../src/pcm_source_anim.cpp#L68)), and on load it sees `<SOURCE RAV_ANIM`, calls our **registered** `CreateFromType("RAV_ANIM")` ([pcm_source_anim.cpp:99-105](../../src/pcm_source_anim.cpp#L99)), then `SetFileName()` with the resolved path. So the binding likely survives **even with stub state** — which is *also* why Story 6.3's cross-machine relink can be near-zero-code. 6.1 therefore **verifies** the native round-trip and **implements a real, versioned `SaveState`/`LoadState` framework with a defensive `file=` fallback**, so the gate passes whether or not Reaper writes `FILE` for our custom type. [Source: [architecture.md:317-329](../planning-artifacts/architecture.md#L317) D9; [architecture.md:580-596](../planning-artifacts/architecture.md#L580) `key=value` format; [sprint-change-proposal-2026-06-27.md §1](../planning-artifacts/sprint-change-proposal-2026-06-27.md)]

### The PCM_source state mechanism (SDK ground truth)

`PCM_source::SaveState(ProjectStateContext* ctx)` and `LoadState(const char* firstline, ProjectStateContext* ctx)` are the SDK virtuals ([reaper_plugin.h:609-610](../../extern/reaper-sdk/sdk/reaper_plugin.h#L609)). `ProjectStateContext` ([reaper_plugin.h:362-377](../../extern/reaper-sdk/sdk/reaper_plugin.h#L362)) gives you exactly two I/O calls:
- **Write:** `virtual void AddLine(const char* fmt, ...)` — printf-style; **the format string must be a literal** (build the line yourself and emit `AddLine("%s", line.c_str())` so a `%` in a path can't be interpreted).
- **Read:** `virtual int GetLine(char* buf, int buflen)` — **returns `-1` on eof**; loop until then.

`SaveState`/`LoadState` are **virtuals Reaper calls during project save/load** — they are **not** registered. So this story adds **no** `rec->Register` and touches **no** `WANT_` symbol; `ProjectStateContext`/`PCM_source` are already visible through [reaper_api.h](../../src/reaper_api.h)'s SDK include. [Source: [reaper_plugin.h:362-377, 609-610](../../extern/reaper-sdk/sdk/reaper_plugin.h#L362); [architecture.md:305-311](../planning-artifacts/architecture.md#L305) PCM_source method list]

### The `file=` fallback must never override native relink — the `only-if-empty` rule (AC4, 6.3-compat)

This is the one decision that, done wrong, **breaks Story 6.3**. If `LoadState` unconditionally `SetFileName`'d from our saved `file=`, then on a project moved to another machine (where Reaper relinked the native `FILE` to the new local path) our **stale** `file=` from the origin machine would clobber the good relinked path → missing media. The fix is the **`only-if-empty` guard**: apply `file=` **only when `m_path` is empty**. Walk the two orderings:
- `LoadState` runs **before** Reaper's native `SetFileName`: `m_path` is empty (from `CreateFromType("")`) → we set it from `file=` → Reaper's native `SetFileName(relinked)` then **overrides** → native wins.
- `LoadState` runs **after** native `SetFileName`: `m_path` already holds the relinked path → our `file=` is **skipped** → native wins.

Either way the native/relinked path is authoritative and our `file=` only fills a gap Reaper left empty. It is **strictly safer than the stub** (it can only *add* a binding, never remove or wrong one) and keeps 6.3 a native, verify-first story. [Source: [pcm_source_anim.cpp:70-75](../../src/pcm_source_anim.cpp#L70) `SetFileName` re-probes `m_len`; [prd.md:431](../planning-artifacts/prd.md#L431) FR46 native relink; [architecture.md:493](../planning-artifacts/architecture.md#L493) Phase 4 native portability]

### Forward-compat & data-safety fall out of two primitives (AC3, AC4, NFR-R2)

The whole AC3/AC4 contract reduces to: **`SaveState` writes only our `key=value` lines; `LoadState` parses `key=value` and ignores everything else, never erroring.** The `key=value` splitter that returns "ignore" for any line without a `=` (or with an empty key) makes `LoadState` automatically tolerate (a) **unknown future keys** (forward-compat — a newer project's extra keys), (b) Reaper's **native `FILE "…"` line** (no `=` → ignored — Reaper handles `FILE` itself), and (c) **nested `<…>` blocks** (the opener has no `=`; the `>` sentinel is handled explicitly). Returning `0` (never `-1`) on a parse miss is what guarantees "a single bad line never drops the item." And `SaveState` calling **only** `ctx->AddLine` (no Reaper mutation API, no writing outside our chunk) is what guarantees NFR-R2 "never corrupt the project / drop tracks / touch other state." [Source: [architecture.md:329](../planning-artifacts/architecture.md#L329) ignore-unknown; [architecture.md:1020](../planning-artifacts/architecture.md#L1020) NFR-R2↔D9; [prd.md:447](../planning-artifacts/prd.md#L447) NFR-R2]

### Restoration is end-to-end and rides the existing pipeline — no viewer change (AC2, AC5)

Once a reopened source comes back **with its path**, the rest is **already wired** and must stay untouched: the viewer's `RenderTick` polls `GetCurrentAnimItem` ([pcm_source_anim.cpp:160-225](../../src/pcm_source_anim.cpp#L160)) every frame, finds the rebound item under the playhead, lazily loads its asset on path-change (4.3), and `RenderFrame` drives the frame (4.3–4.5, with 4.4's `D_STARTOFFS` left-trim and 4.5's topmost-track selection). So 6.1's *entire* job is making the **source object reappear bound to its file** — the transport→display chain then restores the visible state for free. **Do not** add restore logic to `viewer_window.cpp`/`renderer.*`; if you find yourself editing them you have left scope. [Source: [pcm_source_anim.cpp:160-225](../../src/pcm_source_anim.cpp#L160) `GetCurrentAnimItem`; Story 4.3 RenderTick path-change reload]

### Why camera/offset/scale are deferred, not persisted (AC5, Task 5)

The D9 format names optional keys `cam_*`, `time_offset`, `time_scale` ([architecture.md:589-596](../planning-artifacts/architecture.md#L589)) and AC1 calls them **optional** — 6.1 deliberately persists **none** of them, because none is *ours to write today*:
- **Camera is global, not per-item.** The renderer owns one `OrbitCamera` (`cam_`), reset on `SetAsset` ([Story 2.4 sprint note](sprint-status.yaml)); there is **no per-item camera storage**. Persisting per-item camera is a real feature (source fields + viewer push-on-change + pull-on-item-switch) — out of scope, deferred with a concrete trigger.
- **`time_offset` is native.** Left-trim is take `D_STARTOFFS`, persisted **by Reaper natively** and already consumed by 4.4's `GetCurrentAnimItem`. Writing our own `time_offset` would duplicate native state (and risk the same override hazard as `file=`).
- **`time_scale` is native + already deferred.** Take `D_PLAYRATE`, deferred since 4.4.

Persisting them now would be scope creep with no current source of truth. The honest 6.1 persists the **binding** (the one thing that would otherwise be lost) and stands up the **versioned framework** future per-item state plugs into. [Source: [architecture.md:589-596](../planning-artifacts/architecture.md#L589); [deferred-work.md](deferred-work.md) `D_PLAYRATE` from 4.4]

`SaveState`/`LoadState` add **no** registration — the boundary rule (`rec->Register` only in `plugin_main.cpp`, [architecture.md:875](../planning-artifacts/architecture.md#L875)) is preserved; **confirm it, don't touch `plugin_main.cpp`**.
