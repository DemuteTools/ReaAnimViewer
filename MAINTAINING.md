# Maintaining ReaAnimViewer

Everything a maintainer does is a double-click on one of the `.bat` files at the root of the repository. They work on any Windows PC and install the tools they need on first use.

## Repository Layout

| Path | Content |
|------|---------|
| `src/` | Extension source code (C++) |
| `cmake/`, `CMakeLists.txt` | Build configuration. Dependencies are fetched and statically linked. |
| `extern/` | Vendored third-party headers (REAPER SDK) |
| `Icons/`, `tools/gen_icons.py` | Viewer menu icons and the script that converts them to `src/overlay_icons.h` |
| `Extensions/ReaAnimViewer.ext` | ReaPack package definition (version, changelog, download URL) |
| `index.xml` | ReaPack index, **generated** by GitHub Actions. Never edit it by hand. |
| `.reapack-index.conf` | reapack-index settings (repository name, ignored folders) |
| `.github/workflows/` | CI: validates the package on every push, regenerates `index.xml` on `main` |
| `docs/` | User documentation |
| `scripts/` | Helpers used by the `.bat` files |

Private dev files (`.claude/`, `_bmad/`, `_bmad-output/`, `CLAUDE.md`, validation gate docs) are ignored by this repository and synced separately with `dev-sync.bat`.

## Scripts

| Script | What it does |
|--------|--------------|
| `build.bat` | Builds the extension and installs it into REAPER. Double-click = release build. |
| `release.bat` | Publishes a new version (see [Releasing](#releasing-a-new-version)). |
| `reapack-check.bat` | Validates the ReaPack package locally with `reapack-index --check`. |
| `dev-sync.bat` | Syncs the private dev files between your PCs. |

### build.bat

```
build.bat [release|debuglog|forcefail] [clean] [noinstall] [nopause]
```

| Argument | Effect |
|----------|--------|
| `release` | Normal build, the one we ship (default) |
| `debuglog` | Re-enables the `[RAV]` console logs (`RAV_ENABLE_CONSOLE_LOG`), built in `build-debuglog/` |
| `forcefail` | Forces the OpenGL init failure path (`RAV_FORCE_INIT_FAILURE`), built in `build-forcefail/` |
| `clean` | Deletes the build folder first |
| `noinstall` | Does not copy the DLL into `%APPDATA%\REAPER\UserPlugins` |
| `nopause` | Does not wait for a key press at the end |

After testing a `debuglog` or `forcefail` build, run `build.bat` again to reinstall the normal build.

## Releasing a New Version

1. Commit your work on `main` (the release script refuses uncommitted changes).
2. Double-click `release.bat`. It:
   - installs and logs in GitHub CLI if needed,
   - asks for the new version (`0.2.0`, or `0.2.0-beta` for a pre-release),
   - opens Notepad for the changelog (one change per line),
   - makes a clean release build and checks the DLL has no VC++ runtime dependency,
   - updates the version in `Extensions/ReaAnimViewer.ext`, `CMakeLists.txt` and `README.md`,
   - asks for confirmation, then commits, tags `vX.Y.Z`, creates the GitHub Release with `reaper_animviewer.dll` and pushes `main`.
3. GitHub Actions runs `reapack-index` and commits the updated `index.xml` (about one minute). ReaPack and the Demute Reaper Toolkit then offer the update.
4. Run `git pull` to get the `index.xml` commit made by the bot.

Never change `@version` in the `.ext` file by hand: `release.bat` must create the matching GitHub Release, otherwise ReaPack would point to a download that does not exist. The `.ext` starts with `@noindex` until the first release, so nothing is published before that.

The download URL in the `.ext` is built from the `origin` remote, so it follows the repository when it moves to the Demute organization. After the move, update `origin` (`git remote set-url origin ...`) and the repository URLs in `README.md`.

## ReaPack Index

`index.xml` is regenerated by `.github/workflows/reapack-deploy.yml` on every push to `main`, using `reapack-index` like the [official template](https://github.com/cfillion/reapack-repository-template). `reapack-check.yml` validates the package on every push.

To check the package locally before pushing, run `reapack-check.bat`. The first run installs Ruby, Pandoc and reapack-index.

The repository must be **public** for ReaPack users to download the index and the DLL.

## Private Dev Files (dev-sync.bat)

BMAD, Claude Code settings and validation docs live in a private companion repository on your own GitHub account, `<your-user>/ReaAnimViewer-dev`, stored locally in `.devgit/` and sharing this folder as its work tree.

| Command | When |
|---------|------|
| `dev-sync.bat setup` | Once per PC. Creates the private repository the first time, otherwise downloads the dev files. |
| `dev-sync.bat push` | Before leaving a PC |
| `dev-sync.bat pull` | When arriving on another PC |
| `dev-sync.bat status` | To see what changed locally |

Double-clicking `dev-sync.bat` shows a menu. `.claude/settings.local.json` stays local to each PC.
